the pipeline, with actual gates.

Decode → classify → align → build → validate. A production implementation should reject mixed/instrumental-heavy uploads before the TTML generator can run.

1

Decode

Inspect duration, channels, sample rate and usable audio windows.

2

Classify

Use compact spectral and temporal features to identify vocal-like stems.

3

Align

Find vocal activity and fine timing anchors for word-level sync.

4

Build

Construct lyric spans, BG roles, agents and song-part sections.

5

Validate

Check XML structure, timing order, IDs and export integrity.

the stack

Training can be heavy offline. The shipped client should stay small.

TypeScript + JavaScript

Material 3-inspired UI, audio handling, browser orchestration, WebNN bridge and export.

Rust → WASM

Fast, memory-conscious DSP and feature extraction for short audio windows.

Python

Dataset preparation, training, calibration and evaluation of the stem-purity classifier.

Tiny client model

Quantized classifier targeted at CPU-friendly inference. WebNN is an optional accelerator.

Format note: Apple-Music-style TTML tooling documents word timing and structures used for background vocals, singer agents and song-part grouping. This prototype treats those as supported ecosystem structures rather than claiming every internal Apple field is publicly documented.
